# antislop audit 004 (2026-10-07), Git accounts per bot and git access per server/channel

Scope: `apps/web/src/pages/tenant/GuildGit.tsx` (new), the git accounts checklist in `TenantBots.tsx`, the Settings sheet in `GuildInstructions.tsx`, the "Settings" button in `IntegrationServers.tsx`.
Checked in headless Chrome at 360 and 1280 px against the real agent API (temporary SQLite DB, faked Discord guild list). Not checked at 768 px. Contrast was not computed. Real Discord and real GitHub/GitLab were not used.
Code comments: one `eslint-disable-line` in `GuildGit.tsx` (the channel draft effect); it names the rule and is not a restating comment.

1. MEDIUM (R-27, data loss): the sheet has two save paths. "Save server access" and "Save channel access" write immediately, but the bottom "Save" only saves the instructions and closes the sheet. Edits to the git fields that were not saved with their own button are dropped without warning when the sheet closes. Fix: either one bottom Save that writes both, or mark the git section "saved separately" and disable the bottom bar's close-on-save wording.
2. MEDIUM (R-35, tap targets): the account checkboxes are `size-4` (16px) inside rows about 28px tall, in both `GuildGit.tsx` and `TenantBots.tsx`. Same pattern as the older "Always respond in" list. Fix: make the label row at least 44px tall below `sm` (`min-h-11`), keep the box small.
3. MEDIUM (R-27, state loss): changing the channel in the picker replaces the channel draft, so unsaved pattern edits for the previous channel are lost silently. Fix: keep one draft per channel id in state, or ask before switching when the draft differs.
4. LOW (R-35, tap targets): the "Save server access", "Save channel access" and "Follow server" buttons use `size="sm"`, about 32px tall. Fix: default size below `sm`.
5. LOW (R-27, perceivable states): the loading state in `GuildGit.tsx` is `sr-only` text over a skeleton, so sighted users get no wording, unlike the instructions form next to it, which shows "Loading instructions". Fix: visible "Loading git access" text.
6. LOW (R-32, forms): the Repositories input has no `aria-describedby` for the pattern hint, and a rejected pattern ("wider than the server rule", "Invalid repo pattern") only appears as a toast. Fix: link the hint with `aria-describedby`; show the error under the field with `role="alert"`.
7. LOW (copywriting): "Follow server" and the `· custom` suffix in the channel list are terse. A reader may not know that custom means the channel has its own narrower rule. Fix: "Use server rule" and "· own rule".
8. LOW (R-25, unverified): helper text is `text-xs text-muted-foreground`; the pairing was computed for white and `#fafafa` backgrounds in audit 003, but the new `border` rows and `hover:bg-muted` rows were not computed. Fix: run `contrast-check.py` on the tokens in `index.css`.
9. LOW (R-35, unverified): long account names, `provider · username` strings and long patterns in the 512px sheet were not checked at phone width; the account label row has no `break-words`. Fix: check at 360px, add `break-words` and `min-w-0`.
10. LOW (heading order): the sheet title is the sheet's own heading, then the page adds an `h2` "Git access" and `h3` sections. If the sheet title renders as an `h2`, there are two sibling h2s with different weights. Fix: confirm the title level in `components/ui/sheet.tsx` and set the section heading one level below it.

## Measured in the browser (2026-10-07)
- No horizontal page or sheet overflow at 360 or 1280 px. Long account names, usernames and a very long channel name wrap correctly (#9: no problem found, close it).
- #2 confirmed: checkbox label rows measure 20 px tall. #4 confirmed: the three section buttons measure 32 px, Cancel and Save 36 px.
- #10 confirmed: the sheet title and the "Git access" heading are both `h2`, with `h3` sections below.
- Flow checked through the UI against the real API: the channel picker shows "dev-api · custom" with only `work-github` on and pattern `acme/api`; saving the server rule as `acme/web` removed that channel rule (the server rule no longer covers it), and the channel list then showed no rule for it.
- Seen while testing: that pruning is silent. After "Save server access" nothing tells the person a channel rule was removed. New finding below.

11. MEDIUM (R-27, perceivable states): narrowing a server rule deletes channel rules that no longer fit, and the UI says only "Git access saved". Fix: the API returns the ids of the removed channel rules and the toast names them, or the save is refused with a message until the channel rule is changed first.
