# antislop audit 002 (2026-10-07), Git accounts

Scope: `apps/web/src/pages/tenant/TenantGitAccounts.tsx`, the "Git account" field in `TenantBots.tsx`, and `apps/agent/src/routes/admin/gitAccounts.ts`.
Code comments: only one added (`ponytail:` in `migrate.ts`), explains a why, none to remove.

1. HIGH (R-27, loading/error states): the page shows a bare skeleton with no text while loading, and if the list request fails the skeleton stays forever (only a toast, `accounts` never leaves `null`). Fix: a visible "Loading git accounts" line and an inline error with a Retry button.
2. MEDIUM (R-32, keyboard): the delete button for an account in use is `disabled`, so it cannot be focused and its reason ("Unbind integrations before deleting") lives only in the label of a control keyboard users cannot reach. Fix: show the reason as visible text under the integration badges.
3. LOW (R-27, feedback): the Provider select is disabled when editing with no explanation. Fix: helper text "Provider cannot be changed. Create a new account instead."
4. LOW (R-25, unverified): helper text is `text-xs text-muted-foreground`; I did not compute its contrast against the card background. Fix: run the contrast checker on the two tokens in `index.css` before calling it passing.
5. MEDIUM (behavior, security, not antislop): `PATCH /git-accounts/:id` with a new `baseUrl` and no new token verifies the stored token against the new host, which sends the saved token to whatever host was typed. Fix: require a new token whenever `baseUrl` changes.
6. MEDIUM (behavior, security, not antislop): the plan said https-only `baseUrl` also guards against internal targets. It does not; `https://10.0.0.5` passes. Self-hosted GitLab on a private network is a legitimate use, so blocking private ranges would break it. Only platform-admin keys can reach these routes today. Fix options: (a) leave as is and document it, (b) add an optional allowlist env var `GIT_ALLOWED_HOSTS`. Needs your decision.

## Status
#6 fixed on 2026-10-07 with a platform-wide allowed-hosts list editable in the web UI (option b, configurable). #5 fixed the same day: the PATCH refuses a host change without a new token, and the form requires it. #1-#3 fixed. #4 checked with `contrast-check.py` (oklch greys converted to hex): muted-foreground on card is 4.74:1 light and 6.94:1 dark, both pass; muted-foreground on `muted` is 4.35:1 light and fails, but this page never puts it there, so no change. All findings closed.
