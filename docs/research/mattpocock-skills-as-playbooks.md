# Which mattpocock/skills can run as Pachiware playbooks

Research for [#51](https://github.com/yhagus/pachiware/issues/51), child of the map [#50](https://github.com/yhagus/pachiware/issues/50). It builds on the earlier note for #18 on branch `research/mattpocock-playbooks-for-discord` (`docs/research/mattpocock-playbooks-for-discord.md`), which judged a few of these skills for turning a brief into issue drafts. This note judges every skill for a different question: can it run as a playbook at all?

**Upstream source:** `mattpocock/skills` at commit [`49dd158`](https://github.com/mattpocock/skills/tree/49dd158d1076134a641b33efb035946536778336), still the head of `main` on 2026-10-12, so it is the same commit the #18 note read. Upstream paths are cited as `path:line` relative to `https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/`.

**Our source:** `origin/main` at `0759100`. Our paths are cited as `path:line` from the repo root. ADR 0004 (`docs/adr/0004-claude-code-style-skills-become-playbooks.md`) exists only uncommitted in the main checkout on 2026-10-12. Where this note cites it, it uses that uncommitted text.

**Vocabulary:** upstream "skill" = our **Playbook**. Our **Skill** = a bundle of tools (`GLOSSARY.md:59-65`, ADR 0004). This note says "skill" only when it names an upstream folder.

## Short answer

- **Runs with today's tools, after adapting the text (11):** `grilling`, `grill-me`, `grill-with-docs`, `domain-modeling`, `to-spec`, `to-questionnaire`, `wait-what`, `code-review`, `pr`, `codebase-design` (as reference), and `writing-for-agents` (as reference). `ask-matt` also fits as a router once it is rewritten to list only the imported playbooks.
- **Runs once tools are added (3):** `wayfinder`, `to-tickets`, `triage`. They work on the issue tracker, which the git skill covers, but they need operations the git skill does not expose as tools: sub-issues, blocking links, labels on create, and filtered issue queries.
- **Partial (4):** `research` and `teach` need a web fetch tool, which no skill has. `improve-codebase-architecture` needs an HTML report it can open. `handoff` has no fresh agent to hand off to.
- **Does not fit (all others):** they run commands, edit a checkout, start sub-agents in worktrees, or read local session logs. These are `implement`, `implement-spec`, `tdd`, `prototype`, `diagnosing-bugs`, `wizard`, `retro`, `setup-matt-pocock-skills`, `chief-of-staff`, `claude-handoff`, `setup-ts-deep-modules`, and the four `misc` skills. The in-progress `loop-me` and the three `writing-*` skills would fit, because they only keep Markdown files, but upstream says they "can change or disappear without warning" (`skills/in-progress/README.md:3`).
- **License:** MIT. A copy must carry the copyright and permission notice. `pr` also carries a second MIT notice, from HumanLayer.

## What a playbook has to work with

Facts about our runtime that decide every verdict below.

| Fact | Source |
| --- | --- |
| A playbook is a folder with `PLAYBOOK.md`: frontmatter `description`, `trigger` (`menu`, `word`), `requires`, `optional`, then a Markdown body. Built-ins ship in `packages/skills/playbooks/`. A tenant's copy under Workspace `shared/playbooks/` wins by name. | `packages/skills/src/playbooks.ts:7-24`, `:47-58`, `:79-82` |
| A playbook refuses to start while a skill in `requires` is off. | `packages/skills/src/playbooks.ts:96-97`; `apps/agent/src/discord/client.ts:30` |

### Loading graph of the skills that fit

```text
wayfinder ──► grilling, domain-modeling, research, (prototype: not imported)
triage ─────► grilling, domain-modeling
grill-with-docs ► grilling, domain-modeling
grill-me ───► grilling
improve-codebase-architecture ► codebase-design, grilling, domain-modeling

```

Upstream has a rule: a user-invoked skill can load only model-invoked skills. No skill can load a user-invoked one (`.agents/invocation.md:8`, `:22`). Every loaded skill above is model-invoked: grilling, domain-modeling, research, codebase-design, writing-for-agents (frontmatter of each has no `disable-model-invocation`). The map settled that "a playbook may load another playbook that is also available". Upstream adds an invariant we could adopt: loaded playbooks are a separate kind (reference playbooks such as grilling and domain-modeling), and the entry points (wayfinder, triage, to-spec) never load each other.

## What adapting changes, across all imports

1. **Loading.** Rewrite "Call the Skill tool with X" to load playbook X (ADR 0004, Consequences). `readPlaybookFile(X, "PLAYBOOK.md")` already returns the text (`playbooks.ts:99-107`). A real load also has to check X's `requires` and apply X's closed tools.
2. **Frontmatter.** `SKILL.md` becomes `PLAYBOOK.md`. Drop `name` (the folder is the name, `playbooks.ts:13-14`), `disable-model-invocation`, `argument-hint` and `metadata`. Add `requires`, `optional` and `trigger`. Upstream also ships `agents/openai.yaml` per skill (`.agents/invocation.md:10`). It is not needed.
